# 部署到「国内可正常访问」的静态站点

## 为什么现在的地址在国内不好用

站点目前发布在 **GitHub Pages**（`*.github.io`）。这个域名在国内经常
DNS 被污染或速度极慢 —— 不是站点本身的问题，是托管方的问题。

本站是**纯静态**站点（`web/` 目录直接就是全部产物，无构建步骤），
所以换托管方只是把同一个目录换个地方放，不需要改任何代码。

## 三种方案对比

| 方案 | 国内访问 | 费用 | 前置条件 | 落地时间 |
|------|----------|------|----------|----------|
| GitHub Pages（现状） | ❌ 经常打不开 | 免费 | 无 | 已上线 |
| **Cloudflare Pages** | ⚠️→✅ 绑自定义域名后通常可用 | 免费 | 邮箱注册 + 一个域名 | 15 分钟 |
| **国内云 OSS/COS + CDN** | ✅ 最快最稳 | 几元~几十元/月 | **域名实名 + ICP 备案** | 1~2 周 |
| **香港/新加坡轻量服务器** | ✅ 快 | ¥24~60/月 | 购买时需实名 | 1 天 |

> Vercel、Netlify、Gitee Pages 都不推荐：前两者在国内时通时不通，
> Gitee Pages 已不再对个人免费开放。

## 方案 A：Cloudflare Pages（推荐先上这个）

零成本、不需要备案、和现有 GitHub 仓库自动联动。

1. 注册 [cloudflare.com](https://dash.cloudflare.com/sign-up)（邮箱即可，无需实名）
2. 左侧 **Workers & Pages → Create → Pages → Connect to Git**
3. 授权并选择本仓库
4. 构建设置：
   - **Framework preset**：`None`
   - **Build command**：留空
   - **Build output directory**：`web`
5. 点 **Save and Deploy**，几分钟后会得到一个 `*.pages.dev` 地址
6. （强烈建议）**Custom domains → Set up a custom domain** 绑定自己的域名。
   `*.pages.dev` 在国内不稳定，绑上自定义域名后走 Cloudflare 的线路，可用性明显更好

**数据会自动更新**：仓库里的 GitHub Actions 每天抓取数据并 `git push`，
Cloudflare Pages 检测到推送会自动重新部署，不需要额外配置。

## 方案 B：国内云（要「最稳」就选它）

阿里云 OSS / 腾讯云 COS 的静态网站托管 + CDN，速度是国内最好的。代价是需要：

1. **域名实名认证** —— 在域名注册商处提交身份证信息（必须本人操作）
2. **ICP 备案** —— 通过云厂商提交，通常 7~20 个工作日
   （用大陆节点 + 自定义域名就必须备案，这是法规要求，没有绕过方式）
3. 上传 `web/` 目录内容，绑定已备案域名

> 注意：直接用 OSS/COS 的**默认域名**访问 HTML 会被强制下载而不是渲染，
> 所以这条路实际上绕不开「自定义域名 + 备案」。

## 方案 C：香港/新加坡轻量服务器

国内访问快，且**不需要 ICP 备案**（因为服务器不在大陆）。费用约 ¥24~60/月，
购买国内厂商（阿里云/腾讯云）的境外机型时需要账号实名。

部署方式：装 Nginx，把 `web/` 目录丢进去即可，无需构建。

## 两个需要说清楚的点

**关于「永久」**：没有真正永久免费的托管。免费方案都依赖平台本身持续运营；
想让地址长期属于自己，必须拥有一个自己的域名并**每年续费**（域名忘了续费会被回收）。

**关于「登录查看」**：本站是公开数据查询工具，所有人直接打开即可使用，
不需要也不应该有登录 —— 一旦加登录，搜索引擎无法收录、分享链接对方也打不开。
如果你要的是**登录后查看**（比如只给付费用户看），那是另一套架构：
需要后端服务 + 账号体系 + 数据库，成本和维护量都会上一个台阶。

## 本仓库需要改的地方

- **不需要改代码**：`web/` 就是完整产物，任何静态托管都能直接用
- 若用 Cloudflare Pages 并希望继续用 GitHub Actions 自动更新数据：
  保持现有 `.github/workflows/update-data.yml` 不变即可（它会 `git push` 数据变更）
